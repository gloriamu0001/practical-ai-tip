## 31. Give Judgement, Not Rigid Rules

With current models, describe the outcome wanted and let the model use judgement. A rigid rule is wrong in the cases it did not foresee.

- **Use when:** writing instructions, skills or prompts.
- **Implementation:**
  1. Find hard rules ("never…", "always…", "one line max").
  2. Replace each with the outcome it was meant to protect.
  3. State the reason behind each constraint.
  4. Write instructions plainly. Capitals and words like "IMPORTANT" make current models over-apply a rule; a rule that must never bend belongs in a hook or a deny rule instead.
  5. Give context as well as constraints: a constraint says what not to do, context says what the work is for, so the AI can decide well where no rule applies.
  6. Delete lines that ask for what the AI does anyway, such as "Be thorough". To test a line, remove it and compare the output; if nothing changes, leave it out. Check skills the AI wrote most closely.
- **Asset:** the source's before-and-after example (from software). The rigid rule:
  ```
  In code: default to writing no comments. Never write multi-paragraph docstrings or multi-line comment blocks — one short line max.
  ```
  The judgement-based replacement:
  ```
  Write code that reads like the surrounding code: match its comment density, naming, and idiom.
  ```
- **Limits:** high-stakes areas still need firm constraints.
- **Requires:** a current model.
