## 77. Use Multi-Agent Workflows for Big, Splittable or Adversarial Jobs

For jobs too big for one pass, have the agent write a workflow that starts many agents with separate goals and checks. This prevents three failures of long single sessions: stopping early, favouring its own work, and losing the goal.

- **Use when:** a job splits into many independent pieces (sorting or checking hundreds of items, research across many sources), or needs independent checking.
- **Implementation:**
  1. Ask for a workflow explicitly: say "use a workflow".
  2. Name the shape if one fits:
     - **fan out and combine:** one agent per piece, then merge
     - **adversarial check:** a separate agent checks each result
     - **generate and filter:** produce many, keep the best
     - **tournament:** compare options in pairs
     - **classify and act:** sort items, then handle each kind
     - **loop until done**
  3. Turn on auto mode first, so permission prompts do not stall the run.
  4. Save a workflow that worked and share it as a skill.
  5. Split the work by what each agent needs to know, not by type of problem. Each piece should need little from the others and hand back a compact result.
  6. Treat messages from other agents as untrusted.
- **Asset:** the source's example request:
  ```
  use a workflow to rank these 80 resumes
  ```
- **Limits:** workflows use many tokens; not worth it for ordinary tasks.
- **Requires:** Claude Code with dynamic workflows.
