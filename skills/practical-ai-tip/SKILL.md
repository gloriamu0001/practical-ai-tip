# Practical AI tip

Share the few tips from the tip bank (89 tips, last reviewed 2026-11-14) that best fit the user's situation.

- **Input:** the conversation so far, plus optional text after the command: a struggle ("it keeps ignoring my rules"), the kind of tip wanted ("tips on checking quality"), a tip number, or "all".
- **Output:** one short chat reply.
- **Limits:** read only the files of this skill. Write no files, keep no record of tips shown, and fetch nothing from the network. Share tips only in the reply to this request; later replies carry no tips unless the user asks again.

## Files

- This file: the lookup rules and the trigger table, one row per tip.
- `tips/<number>.md`: the full text of one tip, with its sources. Example: `tips/40.md`.
- `browse.md`: all tips by topic group, with each tip's key action.

## Find the tips

1. **Read the situation.**
   - With input, the input is the main signal. A struggle matches situations in the table. A kind of tip matches a topic group in `browse.md` and the situations of that group's tips.
   - Always scan the conversation history for situations in the table: what the user is doing or about to do, repeated corrections, complaints, tools being connected, and actions about to happen, such as sending, deleting or running unattended. With no input, the history is the only signal.
   - Note the tool the user works in or asks about: Claude Code, Cowork, a plain chat, or another agent such as Codex, Gemini CLI, GitHub Copilot, Cursor or Windsurf.
2. **Pick candidates.** A candidate needs a strong match: the user's words or an observed event fit one of its situations. A shared topic word alone is not a match. Drop a candidate when its "Not when" fits, or when its "Works in" excludes the tool. "any" fits every tool.
3. **Rank the candidates.**
   1. Priority 1 first: safety and actions that are hard to undo.
   2. Then the tip that fits the input, or the most recent struggle, most specifically.
   3. Then priority 2 before priority 3.
4. **Confirm.** Read the tip file of each tip to share, and check its "Use when" and "Limits" against the situation. Drop a tip that does not fit.

A tip number as input shows that tip. "all" shows `browse.md`.

## Share them

Share at most three tips. One change the user can make now helps more than a reading list.

- **One tip fits:** write one line on why it fits, then show the full tip.
- **Two or three fit:** write a numbered item for each, then one closing line: "Ask for a tip number to see the full tip."
  ```
  1. **Tip 38: Rewind Instead of Correcting.** Rewind to before the mistake and prompt again with the lesson, instead of correcting afterwards.
     Fits because: the same draft was corrected three times.
  ```
  The example is illustrative. Quote the nudge exactly as the table gives it, because it follows the tip writing rules. Write the "Fits because" line from what the conversation shows.
- **None fits:** say so in one sentence. Without input, ask what the user struggles with or wants to improve, and list the topic groups of `browse.md` with their tip counts. With input, offer the closest topic group.
- **Full tip:** show the tip file as written: title, summary, fields, asset and sources. Keep "(Unverified)" and the Status line when the tip has them.

Write as the tips are written: plain words, the imperative, and no personal pronouns in tip text.
