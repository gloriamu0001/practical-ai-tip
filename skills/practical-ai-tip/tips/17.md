## 17. Put the Whole Brief in the First Message

State the goal, the constraints and how success will be checked in the first message, so the agent plans around the whole problem and fewer corrections are needed later.

- **Use when:** starting any task bigger than a quick question.
- **Implementation:**
  1. **Goal:** what success looks like, described as the finished result, not the steps to get there, and when the AI should stop and ask.
  2. **Constraints:** what is out of scope, what must not be touched, fixed requirements. Where the method itself matters (legal, safety, compliance), state the required steps as constraints.
  3. **Acceptance criteria:** how the result will be checked, ideally as a detailed list of statements that can each be checked.
  4. Say how far to go. The AI reads requests conservatively and builds the smallest thing that satisfies them, so ask for the fuller version explicitly when it is wanted.
  5. Say what a high-quality result looks like, and let the AI propose the steps. Name a method or style by its exact term.
- **Asset:** the source's template (its example task is software; keep the three headings):
  ```
  Goal: add rate limiting to the /api/login endpoint

  Constraints:
  - don't modify the DB schema
  - keep the existing auth flow unchanged
  - use Redis (already configured)

  Acceptance criteria:
  - 5 req/min per IP, returns 429 on limit
  - existing tests still pass
  - new test case for the rate-limit behavior
  ```
  A fill-in scaffold from an official source, for business tasks:
  ```
  Help me with [task] for [business]. Context: [audience, situation and approved information]. A useful result is [format, length, tone and success criteria]. Ask only essential questions before starting. Separate verified facts from assumptions, and flag missing information. Keep the result in draft for my review. Do not send, publish, schedule or edit records.
  ```
