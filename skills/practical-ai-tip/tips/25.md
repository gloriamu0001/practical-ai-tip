## 25. Write Down What the AI May Do, What a Person Decides, and When It Stops

Before building a workflow that others will use, write down what the AI may do, what stays with a person, and when the workflow stops, asks or escalates.

- **Use when:** setting up an AI workflow for a team or for repeated use.
- **Implementation:**
  1. Decide which tasks the AI may complete or prepare, and which decisions people keep.
  2. Write down the approved tools, data, connections and permissions, and whether each needs read-only or write access.
  3. Write down what the AI must and must not do.
  4. Write down when a person reviews, and when the workflow stops, asks or escalates. As a minimum, the AI asks before it spends money, contacts outsiders, opens sensitive material or takes an action no one authorised. Name the exact actions that need approval, for example "sends anything to a customer or supplier" rather than "contacts outsiders": a broad rule also holds back routine messages to colleagues.
  5. For an agent that lives in a shared channel, give each channel one job and its own standing instructions: where to answer from, to link sources, to ask for a real example instead of guessing, to say when something is unverified, and what needs a person's approval.
  6. Then build the workflow and test it on realistic cases.
- **Asset:** an official source's starter instruction for a reporting channel:
  ```
  @Claude remember for this channel: draft each recurring report from our threads, docs, and data, and link your sources. Nothing goes out until a person approves it. If a report keeps getting the same edits, suggest updating these instructions.
  ```
  A requirements template for one agent; the source also shows it filled in for an agent that prepares a brief before a customer call:
  ```
  Workspace Agent Requirements Doc: [Agent Name]
  Agent mission
  What does the agent do? What output does it produce?
  Scope and boundaries
  What are the specific tasks this agent should do, in order?
  Inputs and trusted context
  What information does this agent need to know to be successful?
  Tools and permissions
  What external systems should the agent have access to? What does it need read-only access vs write access?
  Output requirements
  What should the agent produce by the end of the workflow?
  Quality checklist
  What does a good output look like?
  Human-in-the-loop and escalations
  When should the agent stop and ask for assistance or review?
  ```
