## 56. Build a Small Test Set Before Changing a Workflow

Before changing how an AI workflow is built, make a small set of test tasks, so each change can be compared with how the workflow worked before.

- **Use when:** changing the instructions, tools or structure of a workflow that already works.
- **Implementation:**
  1. Collect a small set of representative tasks with known good results.
  2. Include a task for each chain of steps that runs together, and for each rule the workflow must not break.
  3. Grade the final result against a rubric, and run each task more than once.
  4. Change one thing at a time. Compare with the previous version, and look at which tasks changed, not only the overall score.
  5. Keep a change only if it holds up.
  6. Test on representative cases, including ambiguous and out-of-scope ones, using fictional or de-identified material at first.
  7. When a new model arrives, or a practice is recommended online, use public benchmarks only to decide whether to try it. Decide with the test set, comparing cost as well as quality.
- **Limits:** some problems show up in only one run out of two; systems that are hard to replay are harder to test.
