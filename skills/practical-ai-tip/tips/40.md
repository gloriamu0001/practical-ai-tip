## 40. Give the AI a Way to Check Its Own Work

The single most important lever for output quality: an agent that can check its result keeps working until the check passes.

- **Use when:** delegating any work whose result can be checked.
- **Implementation:**
  1. Pick a check that fits the work: a checklist the draft must pass, a validator for a data format, a test, a browser view of a web page.
  2. Write the check down as a skill, so the agent runs it every time.
  3. Prefer checks that block the result until they pass over checks that only warn.
  4. For a long unattended run, ask the agent to verify the result end to end before it stops.
  5. After the AI reports "done", have it run the real thing and look at the result. Example of a non-code check from a source: a dashboard's labels do not overlap, and its text matches its numbers.
  6. For work other than code, check against a rubric or a style guide.
  7. When no check exists yet, have the agent build one before the work starts, for example reference results from a trusted source to compare against. A question a source asks the agent:
     ```
     How do we make this change fully verifiable?
     ```
- **Limits:** a weak check can be gamed; unnamed kinds of problem slip through; models check visual, animated and interactive output poorly.
- **Requires:** a check that can be run; for browser checks, a browser tool such as Claude in Chrome.
