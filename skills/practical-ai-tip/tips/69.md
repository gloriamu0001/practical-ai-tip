## 69. Supervise First, Then Run Unattended With a Cap and Isolation

Learn how an agent behaves on a task by watching single runs, before letting it run alone. Then cap the number of rounds and isolate it from anything it must not touch.

- **Use when:** planning to let an agent work through tasks unattended.
- **Implementation:**
  1. Run one round at a time and watch. Refine the prompt until it works reliably. Until the agent's mistakes are understood, leave every action on ask-first approval (the default), and keep approval on for anything that sends, spends or deletes.
  2. Only then run many rounds unattended. Always cap the rounds; the source uses 5–10 for small jobs and 30–50 for large ones.
  3. Isolate the agent so it reaches only the folder it needs, in the most restrictive mode that still works, for example in a container or sandbox. Back up anything that cannot be lost.
  4. Set up a notification for when the run ends.
  5. Before leaving a run alone, check five things: it knows what "done" looks like, it can check its own work, it can touch only what it should, something stops it (a cap on turns or spend), and a person approves the result.
  6. Keep agent work away from live systems until it has passed a check.
  7. Widen the agent's freedom one type of task at a time, as its checked results prove reliable. Widen volume the same way: start with one item a day, check and adjust, then two, five, ten.
- **Limits:** isolation limits where the agent acts, not what it does there; containers may not load personal instructions and skills.
- **Requires:** an agent with an unattended mode; for isolation, a sandbox or a container tool such as Docker Desktop.
