## 78. Set Token Budgets, and Pilot Before Scaling

Large and repeated runs can use tokens fast. Match the compute to the task, test on a small run first, and check where the tokens go.

- **Use when:** running long, parallel or scheduled work.
- **Implementation:**
  1. Cap tokens in the request, for example "use 10k tokens."
  2. Pilot a small run before a large one.
  3. Use scripts for steps that never change, instead of the model, and smaller, cheaper models for routine work in a repeating loop.
  4. Do not schedule more often than needed: a routine every 15 minutes runs almost 100 times a day. Run recurring jobs in a fresh session, not in a long conversation, which makes each run cost more.
  5. When limits run out fast, check usage per skill, connector and plugin with `/usage`.
  6. Leave the defaults alone until a task costs too much, then check where the cost went.
  7. Set ceilings on cost, rate or tokens.
- **Limits:** the effort setting changes how much work the AI does but does not cap it.
- **Requires:** Claude Code for `/usage`.
